# 決策紀錄（Sean 版）

> 每筆格式：編號、日期、決定、原因、影響。新紀錄加在最上方。

## D113 — 2026-10-19：系統密鑰放 Supabase Vault，由資料庫自動產生

- 決定：`ADMIN_SESSION_SECRET`、`CRON_SECRET`、`WEBHOOK_VERIFY_TOKEN` 在資料庫內以 `gen_random_bytes` 產生並存 Vault；Edge Function 啟動時讀取，secrets 有同名值時以 secrets 為準。驗證權杖顯示在後台「帳號設定」供複製。
- 原因：Sean 不是工程師，少一個要手動產生、保管的值；值從未出現在對話或檔案中。pg_cron 也能直接從 Vault 取 `CRON_SECRET`，兩邊自然一致。
- 影響：換 Supabase 專案時要重新執行 `supabase/setup/01_密鑰與排程.sql`。驗證權杖對已登入的管理者可見（它只用於 Meta 訂閱握手，不是存取權杖）。

## D112 — 2026-10-19：後台用 Bearer 權杖，不用 Cookie

- 決定：登入與初始設定回傳權杖（與原 Session Cookie 同格式、同 8 小時效期），前端存 localStorage，請求帶 `Authorization: Bearer`；CORS 與 CSRF 只允許 `ADMIN_ORIGINS`（預設 `https://seanchen0427.github.io`）。
- 原因：後台在 github.io、API 在 supabase.co，瀏覽器會擋第三方 Cookie（Safari 一律擋）。
- 影響：權杖存在瀏覽器，有 XSS 時可被讀取（Cookie HttpOnly 不會）。後台沒有使用者產生的 HTML、React 預設跳脫，風險可接受。登出只清除瀏覽器的權杖，伺服器端無法撤銷，靠 8 小時到期。

## D111 — 2026-10-19：佇列改用資料表＋每分鐘排程

- 決定：webhook 寫入 `event_jobs` 後立即以 `EdgeRuntime.waitUntil` 背景處理；pg_cron 每分鐘呼叫 `/api/internal/tick` 處理延遲重試與被中斷的工作。認領用條件更新避免重複處理；執行中超過 5 分鐘視為中斷。
- 原因：Supabase 沒有 Cloudflare Queues。Supabase 有 pgmq，但需要另外的消費者，資料表加排程最簡單、可測試（PGlite）。
- 影響：重試最短間隔約 1 分鐘（原本 Queue 可到秒級），對私訊自動回覆沒有實際影響。每月約 4.3 萬次排程呼叫，在免費額度內。

## D110 — 2026-10-19：Edge Function 打包成單一檔案並提交

- 決定：`scripts/build-function.mjs` 用 esbuild 把 `src/` 打包成 `supabase/functions/api/index.ts`，第三方套件改寫成 `npm:套件@版本`（不打包）；壓縮後再排版成多行。打包檔提交進 repo，CI 檢查與原始碼一致。
- 原因：原始碼的 import 沒有副檔名，Deno 不能直接執行；打包後單檔即可用 Supabase MCP、CLI 或後台編輯器部署。
- 影響：改 `src/` 後要記得 `npm run build:function`。

## D109 — 2026-10-19：後端改 Supabase，後台改 GitHub Pages

- 決定：Sean 指定 GitHub repo `SeanChen0427/CHAT` 與 Supabase。後端改為 Supabase Edge Function＋Postgres，後台前端由 GitHub Pages 提供。
- 原因：Sean 要的是網頁工具，不想在電腦安裝東西；Cloudflare 版需要本機跑 wrangler 部署。Supabase Edge Functions 不能對外提供 HTML 頁面，所以前端與隱私權頁放 GitHub Pages。
- 影響：資料庫從 SQLite 改為 Postgres，所有測試改用 PGlite（記憶體 Postgres），288 項全過。上游是 Cloudflare 版，日後合併上游要多做一層轉換。免費方案 7 天無活動會暫停，以每分鐘排程與每日健康檢查避免。

## D108 — 2026-10-19：進階功能保留但預設收合

- 決定：追蹤、Email、標籤、每人一次的程式與測試保留，編輯器中收進「進階（選用）」並預設收合；已使用這些功能的規則會自動展開。
- 原因：Sean 確認核心需求只有三項，介面要簡單；但這些功能已完成且有測試，移除的風險與成本高於收合。
- 影響：預設行為與原版相同（第一則私訊直接給連結）。

## D107 — 2026-10-19：Facebook 沿用同一張帳號／貼文表，以 platform 區分

- 決定：粉專存在 `instagram_accounts`（`platform = 'facebook'`、`instagram_account_id` 存粉專 ID），粉專貼文存在 `instagram_media`。
- 原因：引擎、規則、執行紀錄、統計、後台都以這兩張表為中心；另開表等於複製一套。保留上游表名，日後合併上游更新比較容易。
- 影響：表名與實際內容不完全相符，已在 schema 註解與 AGENTS.md 說明。

## D106 — 2026-10-19：Facebook 用粉專權杖＋graph.facebook.com，與 Instagram 分開

- 決定：Instagram 維持上游的 Instagram 登入版（graph.instagram.com）；Facebook 另用 `FACEBOOK_PAGE_ACCESS_TOKEN` 走 graph.facebook.com。兩個 client 由 `clientFor(deps, platform)` 選擇。
- 原因：改用「Facebook 登入版」統一兩個平台需要重寫上游整個 Instagram 路徑與權杖流程；分開只需新增，不動既有已測試的路徑。兩邊的私訊格式（recipient.comment_id、按鈕範本）相同，引擎大部分邏輯可共用。
- 影響：需要兩組 secret（`FACEBOOK_PAGE_ACCESS_TOKEN`、`META_APP_SECRET`）。粉專權杖由長效使用者權杖換得時不會過期，不需續期邏輯。

## D105 — 2026-10-19：新 token 存在 D1，優先於 secret

- 決定：續期後的 token 寫入 `instagram_accounts.access_token`，所有 Meta 呼叫優先使用；沒有才用 `INSTAGRAM_ACCOUNT_ACCESS_TOKEN` secret。
- 原因：Worker 無法改寫自己的 secret。原版只有到期提醒的註解，實際上 `token_expires_at` 從未寫入，60 天後會無聲失效。
- 影響：D1 內有一份明文 token（D1 屬於 Sean 自己的 Cloudflare 帳號，只有帳號持有者能讀）。log 與稽核紀錄都不寫 token。若要強制換回 secret，把該欄位清空即可。

## D104 — 2026-10-19：門檻流程一律先送按鈕，查詢失敗放行

- 決定：有追蹤或 Email 門檻時，第一則私訊帶「領取」postback 按鈕；按下後才查追蹤。查詢失敗（使用者未同意、網路錯誤）時放行。
- 原因：User Profile API 需要「使用者同意」（傳過私訊或按過按鈕），只留言的人查不到。ManyChat 也是同樣做法。寧可放行也不卡住真正想要資料的人。
- 影響：門檻規則比原版多一次點擊。

## D103 — 2026-10-19：私訊類觸發沿用 automations 表，用 apply_scope 區分

- 決定：私訊關鍵字與 ref 觸發用 `apply_scope = 'dm_keyword' | 'ref'`，不綁貼文，關鍵字存在原本的 `automation_keywords`。
- 原因：上游已用 `apply_scope` 區分 `media`／`next_post`／`account_default`，沿用可以共用編輯器、啟用檢核、執行紀錄與統計，改動最小，日後合併上游也比較容易。
- 影響：私訊類規則的執行紀錄 `instagram_media_id` 為空字串。

## D102 — 2026-10-19：私訊類事件走同一個 Queue

- 決定：postback、referral、一般私訊在 webhook 接收端寫入 `webhook_events` 後入列，`eventType = 'messaging'`，由 consumer 分派到 `funnel.ts`。
- 原因：沿用上游「webhook 不等 Meta API、先回 200」與冪等設計；Meta 重送時 `event_key` 去重。
- 影響：上游原本刻意忽略一般私訊，相關測試已改為新行為。

## D101 — 2026-10-19：以 pjwang2022/instagram-comment-dm-bot 為基礎 fork

- 決定：Sean 指定以此專案為基礎，補上缺少的功能；原本自建的 v0.2 封存。
- 原因：上游 MIT 授權、繁中文件、架構成熟（Queue、熔斷、送出限額、緊急停止、228 項測試），但缺追蹤檢查、Email、標籤、名單、廣告觸發、token 續期。
- 影響：新增程式碼都標註「Sean 版」，方便追上游更新。保留原作者 LICENSE 與版權。
